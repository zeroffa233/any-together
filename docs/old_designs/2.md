# AnyTogether 项目架构设计方案 (v1.0)

### 1. 项目概述

- **项目名称**: `AnyTogether`
- **愿景**: 创建一个桌面应用，允许用户在局域网上组网，与他人实时同步共享和控制本地或者互联网上任何类型的媒体资源。
- **核心技术栈**: Rust (后端核心), Tauri (桌面应用框架), TypeScript (前端逻辑)。
- **核心设计哲学**:
    - **高度可扩展**: 通过动态化的插件系统，支持未来无限扩展新的资源类型。
    - **职责清晰**: 严格分离后端业务逻辑与前端视图控制。
    - **类型安全**: 即使在 Rust 与 TypeScript 的语言边界，也要通过工具保证类型安全。

### 2. 核心架构原则

1. **统一资源模型 (Unified Resource Model)**
    - 所有资源，无论是远程 Web 资源 (`https://...`) 还是本地文件 (`D:/.../video.mp4`)，最终都将被统一为 **HTTP URL**。
    - 由**主机 (Host)** 的 Rust 程序内嵌一个轻量级 HTTP 服务器（例如使用 `axum` 库），当加载本地文件时，主机会将其作为静态资源提供服务，并生成一个临时的局域网 URL (`http://<host-ip>:<port>/<resource-id>`)。
    - 这个模型极大地简化了整体架构，消除了对“原生适配器”和“Web 适配器”的双轨处理，所有适配器都将基于 Web 技术。

2. **数据驱动的适配器系统 (Data-Driven Adapter System)**
    - 适配器的注册和发现机制将完全由一个**配置文件**驱动，而非硬编码在 Rust 代码中。
    - 我们将创建一个 **`adapters.json`** 文件作为适配器的“注册清单”，其中定义了每个适配器的名称、以及它能处理的 URL 的正则表达式。
    - Rust 后端将作为一个**通用的“智能网关”**，在启动时读取此 JSON 文件，并根据其内容进行后续的适配器分发。
    - 增加对一个新网站的支持，主要工作是编写一个新的 TS 适配器和在 JSON 中增加一个条目。

3. **完全通用的动作协议 (Fully Generic Action Protocol)**
    - 为了支持“任何”资源，Rust 与 TS 之间的动作通信协议必须是完全通用的。
    - 我们将使用一个单一的 `GenericAction` 结构体来表示所有操作，它包含一个动作名称（`name: String`）和一个动作参数（`payload: Value`）。
    - Rust 后端**不理解**这些动作的具体含义（如 `toggleDanmaku`），它只负责作为“信使”进行从控制端到其他接受端透明的转发。所有动作的解释和执行逻辑都位于前端的 TS 适配器中。

4. **编译时跨语言类型安全 (Compile-Time Cross-Language Type Safety)**
    - 所有在 Rust 和 TS 之间共享的数据结构（定义在 `protocol.rs`），将以 **Rust 代码为“单一事实来源”**。
    - 我们将使用 **`ts-rs`** 这个库，在编译时根据 Rust 的结构体定义，自动生成相应的 TypeScript 类型声明文件 (`.d.ts`)。
    - 这确保了前端在构建发送给 Rust 的数据时，能享受到编译器的类型检查，从根本上杜绝了跨语言边界的类型不匹配错误。

### 3. 组件详解

1. **网络与会话管理 (`session` 模块)**
    - **协议**: WebSocket (`tokio-tungstenite` 库)。
    - **角色**:
        - **主机 (Host)**: 启动 WebSocket 服务器，管理所有客户端连接，维护会话的权威状态（SSOT）。
        - **客户端 (Client)**: 连接到主机的 WebSocket 服务器，收发消息。
    - **核心对象**: `Session` 枚举（`Host(HostData)` / `Client(ClientData)`），存在于 `AppState` 中，管理当前会话。

2. **数据协议 (`protocol.rs` & `ts-rs`)**
    - 定义所有共享的数据结构，并全部使用 `#[derive(TS)]` 和 `#[ts(export)]` 进行标注。
    - `User`: 用户信息。
    - `SessionState`: 会话状态，包含一个通用的 `data: Value` 字段。
    - `GenericAction`: `{ name: String, payload: Value }`，唯一的动作传输结构。
    - `ClientMessage` / `ServerMessage`: WebSocket 通信的消息体。

3. **适配器系统 (JSON + Rust 网关 + TS 适配器)**
    - **`adapters.json`**: 项目根目录下的配置文件，内容示例如下：
        ```
        [
          { "adapterName": "bilibili", "urlRegex": "^https?://www\\.bilibili\\.com/video/.*" },
          { "adapterName": "directVideo", "urlRegex": "\\.(mp4|webm|mov)$" }
        ]
        ```
    - **Rust 智能网关 (`adapter_gateway.rs`)**:
        - 启动时读取并解析 `adapters.json`。
        - 提供 `dispatch(uri)` 方法，根据正则匹配返回对应的 `adapterName`。
        - 接收到 `session` 模块转发来的 `GenericAction` 后，原封不动地通过 `emit` 事件广播给所有前端。
    - **TypeScript 适配器**:
        - **`IResourceAdapter.ts`**: 定义所有 TS 适配器必须实现的接口，包括 `handleAction(action: GenericAction)` 和 `getCapabilities(): string[]`。
        - **`*.adapter.ts`**: 每个文件是一个具体的适配器实现，包含所有与特定网站交互的逻辑。
        - **`main.ts` (主控制器)**: 监听来自 Rust 的 `adapter_init` 和 `adapter_action` 事件，负责动态加载并调用当前激活的 TS 适配器。

4. **前端架构**
    - **动态 UI**: 控制按钮等 UI 元素将根据当前激活的 TS 适配器的 `getCapabilities()` 方法返回的字符串数组来动态渲染。
    - **双向通信**:
        - TS -> Rust: 通过 `invoke` 调用 `command` 函数，传递 `GenericAction`。
        - Rust -> TS: 通过 `listen` 监听 `emit` 的事件，接收 `GenericAction` 或其他指令。

### 4. 项目文件结构

```
any-together/
├── .git/ # Git 版本控制目录
├── node_modules/ # 前端依赖
├── src/ # 【前端】源码目录 (由 Vite 管理)
│ ├── main.ts # (已简化) 应用主页的脚本，目前可能为空或只导入CSS
│ ├── injector.ts # 【核心】注入器主逻辑，运行在目标网页中，负责加载适配器和UI
│ ├── adapters/ # TS 适配器目录
│ ├── ResourceAdapter.ts # TS 适配器必须遵守的接口 (建议文件名)
│ │ ├── bilibili.adapter.ts
│ │ └── direct_video.adapter.ts
│ ├── types/
│ | └── bindings.d.ts # 【自动生成】由 ts-rs 从 Rust 自动生成的 TS 类型定义
├── src-tauri/ # 【后端】Rust 和 Tauri 配置目录
│ ├── src/ # <-- Rust 后端核心逻辑的根目录
│ │ ├── main.rs # <-- Rust 程序入口，负责组装和启动 Tauri
│ │ ├── protocol.rs # <-- 核心数据结构定义 (User, GenericAction 等)
│ │ ├── error.rs # <-- 统一的错误处理类型
│ │ ├── state.rs # <-- AppState 全局状态容器
│ │ ├── adapter_gateway.rs # <-- Rust 智能网关 (读取JSON, 分发)
│ │ ├── session.rs # <-- 会话管理与 WebSocket 网络核心逻辑
│ │ └── commands.rs # <-- 所有暴露给前端的 Tauri 命令
│ ├── init.js # 【核心】注入器入口脚本，由 tauri.conf.json 配置
│ ├── tauri.conf.json # Tauri 应用核心配置文件
│ ├── Cargo.toml # Rust 后端依赖与包配置
│ ├── build.rs # (可选) Tauri 构建脚本
│ └── icons/ # 应用图标
├── adapters.json # 【根目录】适配器注册清单 (URL 正则 -> TS 适配器名)
├── package.json # 前端项目信息与依赖
├── index.html # (已简化) 应用启动时加载的“主页”或“欢迎页”
├── pnpm-lock.yaml # (或 yarn.lock, package-lock.json)
├── tsconfig.json # TypeScript 配置文件
└── vite.config.ts # Vite 前端构建工具配置文件
```
