# 适配器设计

1. 可控属性：定义了一系列可以被同步、控制和监听的属性，比如某视频网页的isPlaying等等，用于生成固定的网页状态，以进行基于状态的周期同步。
2. 网页状态：包含所有的可控属性及其值。
3. 获取网页状态的方法：用于获取当前网页状态。
4. 控制方法：对于每个可控属性，必须提供一个或多个可以实现在网页内完全控制这个属性的动作组，比如对于isPlaying，我们理想情况下提供switch、play、pause三个方法。借助所有动作组，我们才能实现两个状态的同步。方法本身不仅要会在网页内执行动作，还要会修改网页状态中的可控属性。
5. 监听方法：对于每个可控属性，我们必须提供至少一个监听方法，当我们通过页面的原生控件修改该属性的时候，方法可以监听并劫持到该动作，并将其转化为对该属性的控制方法执行序列，并把该序列分发给其他客户端用于同步。比如用户在网站点击暂停，适配器可以监听到并劫持，不让原来的暂停动作执行，将其转化为pause()的执行动作，然后分发给所有客户端，再执行该动作序列。
6. 同步方法：输入两个优先级不同的网页状态，输出动作序列，使得低优先级的网页状态执行动作序列后可以变为高优先级的网页状态。

# 通信设计

采用Websocket进行通信，网络层只实现心跳和信息的发送与接收。

# 数据结构设计

### GeneticAction 结构体

该结构体描述了一个动作

1. property
2. method

### WebState 结构体

该结构体描述了网页的状态

1. state: serde::json::Value（属性-值对的集合）
2. timestamp_ms（发送的时间，用于校准延迟）

### User 结构体

1. 用户名
2. 权限枚举（只看、控制和可以控制用户权限的主机）

### 消息设计

主窗口通过方法创建一个窗口叫做web_window，该窗口只完整加载网页的html，窗口加载时默认执行一个inatialize的函数，AppHandle监控该窗口的所有属性，当该窗口url改变的时候，前端给主窗口发送一条消息（“Inatialize”）表明需要针对新页面进行初始化，后端针对新的窗口url调用相对应的初始化代码，注入新的ts脚本
